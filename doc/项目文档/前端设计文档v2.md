## 1. 项目定位与技术栈

### 1.1 项目定位

「文献雷达 · 科研追踪工作台」是一套面向科研人员的 **文献持续跟踪助手** 前端界面，围绕以下核心诉求设计：

- **按研究方向自动追踪最新文献**：用户配置若干"研究方向（订阅）"（含关键词、采集来源、相关度阈值、发表时间窗口），系统周期性拉取新文献并聚合展示。
- **智能问答**：基于个人文献库 + 网络检索，多步协作生成带引用的答案（支持三类检索模式与查询改写、多视角综述）。
- **跟进日志**：记录每次自动追踪的执行情况（拉取/新增/去重/耗时/状态）。
- **轻量配置中心**：跟进频率、通知方式、全局采集来源等偏好设置（后端持久化）。
- **管理员端**：用户管理（启停/角色）、模型管理（模型池 CRUD + 按 agent 绑定模型）。

前端为 **Vue3 单页应用**（`web/`，已构建出 `dist/` 由后端静态托管），与后端 FastAPI 通过 REST 接口联动，全流程真实验证，非 mock 原型。

### 2.1 工作台（dashboard）

- **头部区**：品牌标识（Radar 图标 +「PaperPotato / RESEARCH RADAR」，位于侧边栏顶部，§5.6）。
- **侧栏未读概览**：「未读文献」卡片，点击触发 `auth.refreshUnread()`（GET `/api/unread/summary`），未读 > 0 红色加粗、刷新按钮转圈。
- **欢迎与提示**：按时段问候语 + 今日未读提示（未读 > 0 时红色高亮"今日有 N 篇新文献待查阅"）。
- **操作区**：「新建方向」跳转 `/directions`；「运行跟进」下发自动追踪任务（§6.4）。
- **概览指标**：4 个指标卡——研究方向数 / 运行中数 / 累计文献数 / 未读数（数据来自 `/api/subscriptions` 与未读摘要）。
- **方向卡片区**：按方向渲染卡片（含近 7 天迷你柱状趋势），点击打开该方向的文献弹窗（§6.2）。
- 数据均来自真实接口，`loading` 空态与加载文案齐全。

### 2.2 研究方向（订阅）管理（directions）

- **列表视图**：表格风格列表，每行展示 方向名 + 运行状态徽点（运行中/已暂停）· 文献数、关键词标签组、相关度阈值 + 来源 + 时间窗口、操作按钮区。
- **行操作**：启停（Switch/Play-Pause）、编辑（打开表单并回填 initial）、删除。
- **新建**：点击「新建方向」打开空表单弹窗。
- **表单弹窗**（`SubscriptionForm`）：字段含 方向名称、关键词（输入后回车添加/删除标签）、采集来源多选（`ALL_SOURCES` 候选池 = `['arXiv', 'Semantic Scholar', '万方']`，见 §4.3；Google Scholar 为受限候选不出现在可选池）、相关度阈值滑杆（0-100）、**发表时间范围 `pub_window` 复选三档**（1年内 / 1–3年 / 3年以上，默认勾选"1年内"，可多选并取并集）。保存后通过 `/api/subscriptions` 系列接口（POST/PUT/PATCH/DELETE）真实落库。

### 2.3 文献问答（qa）

- **输入区**：问题输入框 + 「提问」按钮；3 个预设问题快捷入口。检索模式入口提供**三形态**：`phrase` / `paragraph` / `strategy`；另有「查询改写」复选框开关（`rewrite`）。
- **执行区**：提交后展示用户问题气泡，随后按多步协作步骤条逐个点亮（查询改写 → 规划调度 → 拆解问题 → 检索文献库 → 检索网络 → 引用历史 → 复审校验 → 汇总答案），逐步态通过**轮询 `GET /api/qa/{sessionId}/steps`** 驱动（真实任务进度，非本地定时器）；`paragraph` 模式展示"已拆句 N 条并行检索"提示；迭代模式（deep 档位）步骤条右上角展示迭代轮次徽章如「第 2/3 轮」。
- **结果区**：完成后渲染要点答案列表 + 引用来源卡片（可外链），并提供「多视角综述」入口（POST `/api/qa/review`，以 sections 形式分区展示）；结果区下方默认收起「思考过程」折叠面板，展开后展示 Planner 每轮规划记录（任务拆解与路由决策）、工具调用历史（工具名/入参/返回摘要）、Reviewer 质检结果（通过 / 不通过 + 缺陷清单 + 改进建议），交互支持展开收起；降级回退 v3 固定流水线时面板内提示文字为【当前使用旧编排流水线，无主 Agent 思考记录】；迭代模式最终结果区域展示迭代次数标签（如"迭代 3 轮"）与复审质检通过标签。
- 交互链：见 §6.3。答案与引用均由后端真实生成。

### 2.4 跟进日志（logs）

- **统计行**：展示最近次数、累计拉取数、累计新增数。
- **表格**：列含 时间 / 方向 / 来源 / 拉取(pulled) / 新增(added) / 去重(deduped) / 耗时 / 状态 / 简报。
- **状态徽章**：成功（绿）、部分失败（红）、失败（红）、进行中等多态配色。
- 数据来源：`GET /api/follow-up/logs`（或等价接口），与后端任务结果回填。

### 2.5 设置（settings）

- **自动跟进频率**：四选一单选项（每小时 / 每 6 小时 / 每日 / 每周，`FREQ_OPTIONS`），选中态高亮。
- **通知方式**：邮件摘要、浏览器推送两个自绘开关（`role="switch"`）。
- **全局采集来源**：`ALL_SOURCES` 多选（chip 选中态），作为"新建方向时的默认来源集合"。
- 加载 `GET /api/settings`、保存 `PUT /api/settings`，后端持久化；保存时校验至少保留一个来源。

### 2.6 用户管理（admin/users，管理员专属）

> 仅 `role='admin'` 可见可访问；普通用户被路由守卫拦截、侧边菜单不显示入口（见 §5.8）。

- **用户列表**：表格展示 用户名 / 角色徽章（用户·管理员）/ 账号状态徽章（启用·停用）/ 最近登录时间 / 创建时间，支持关键字搜索与分页。
- **状态调整**：启用 / 停用（停用后禁止登录）。
- **角色调整**：普通用户 ⇄ 管理员；对最后一名管理员禁止降级/停用，防止系统失去管理入口。
- 列表数据源 `GET /api/admin/users`，操作后即时刷新。

### 2.7 模型管理（admin/models，管理员专属）

> 仅 `role='admin'` 可见可访问（路由守卫同 §2.6）。管理员维护**模型池**并**为各 agent 绑定模型**（对应 PRD §5.9 F-MODEL-01~05、接口见《详细设计文档.md》§3.8）。

**模型池列表**

- 表格展示：显示名 / 供应商 / `model_id` / 能力标签 / 是否默认 / 状态开关（启用·停用）/ 最近更新，支持筛选与分页。
- **启停开关**：行内 Switch 调用 `PATCH /api/admin/models/{id}/status`；停用后该模型不再出现在"可选模型"下拉，不打断进行中任务；停用默认模型时提示回退。
- **新增 / 编辑模型**：表单（显示名、供应商、`model_id`、`base_url`、`api_key`（仅提交服务端，前端不回显，编辑仅显示"已配置/未配置"）、能力标签、是否默认）；提交 `POST /api/admin/models` / `PUT /api/admin/models/{id}`。
- **为 agent 设置模型**：页内「Agent 模型绑定」区块——按 agent（主 agent、qa_router、summarizer、analyst 等）列出行，每行下拉选择（候选 = 启用且能力匹配的模型），切换即调用 `PUT /api/admin/agents/{agentKey}/model`，即时生效。
- 数据源：`GET/POST/PUT/PATCH /api/admin/models`、`GET /api/admin/agents`，与《AI方案文档.md》§1.1/§2/§6 联动。

## 4. 状态管理与数据模型

### 4.1 状态管理方案

采用 **Pinia** 管理全局状态（`stores/auth.ts`）：

- 全局状态 `auth`：`token / username / userId / role('user'|'admin') / totalUnread / unreadBrief`。
- 持久化：`token / username / userId / role` 写入 `localStorage`，刷新后仍生效。
- **方法**：`login()`（POST `/api/auth/login`，存 token 与 role、未读摘要）、`refreshUnread()`（GET `/api/unread/summary`）、`logout()`（清空本地态与 localStorage）。
- **Getter**：`isLoggedIn`、`isAdmin`。
- 业务数据（订阅 / 文献 / 日志 / 管理端）不入全局 Store，由各视图组件以 `ref` 本地持有并按需从 `api` 拉取——保持轻量、随路由生命周期自然释放。

### 4.2 数据模型（DTO，定义于 `src/api/client.ts`）

以下类型是与后端接口对齐的前端 DTO 契约：

```ts
/** 未读摘要项 */
export interface UnreadItem { subscription_id: number; name: string; unread: number }

/** 研究方向（订阅） */
export interface Subscription {
  id: number
  name: string
  keywords: string[]
  sources: string[]
  threshold: number
  pub_window: string          // 多选时间窗，逗号分隔如 '1Y,3Y+'（默认 '1Y'）
  active: boolean
  last_run_at: string | null
  created_at: string | null
  paper_count: number
  unread_count: number
}

/** 单篇文献 */
export interface Paper {
  id: number
  source: string
  title: string
  authors: string[]
  abstract: string
  journal: string
  published_at: string | null
  url: string | null
  score: number
  is_read: boolean
  journal_level: string
  ccf: string
  cas_zone: string
  arxiv_cat: string
}

/** 跟进日志行 */
export interface FollowLog {
  id: number
  kind: string | null
  direction_name: string | null
  pulled: number
  added: number
  deduped: number
  duration: number | null
  status: string | null
  brief: string
  source_errors: string[]
  started_at: string | null
  finished_at: string | null
}

/** 问答单步（轮询驱动步骤条） */
export interface QaStep { key: string; label: string; status: string; detail: string }

/** 问答步骤聚合（GET /api/qa/{id}/steps；v2.1 编排字段） */
export interface QaSteps {
  steps: QaStep[]
  complexity?: 'quick' | 'normal' | 'deep'                                              // 档位
  loop_counter?: number                                                                 // 迭代轮次（第 N/3 轮）
  tool_calls?: { tool: string; args: Record<string, unknown>; result_brief: string }[]  // 工具调用记录
```

## 5. 关键技术实现说明

### 5.1 布局

- 根布局为横向 flex：`AppLayout` = `aside.app-sidebar`（固定宽度 `w-[280px]`，含品牌区 + 未读概览 + 纵向导航 + 用户区）+ `<main class="flex-1 overflow-y-auto"><router-view/></main>`。

- Tailwind v4 通过 **`@tailwindcss/vite`** 插件在 `vite.config.ts` 接入（无需 postcss 配置），设计令牌统一定义于 `src/styles/main.css` 的 `@theme`。

### 5.8 管理端导航与路由守卫（RBAC）

> 角色来源：登录返回 token 及其负载中的 `role`（`'user'` / `'admin'`），前端存 `auth.role`（localStorage）刷新后仍生效。

| 项          | 实现                                                                                     |
| ---------- | -------------------------------------------------------------------------------------- |
| 角色来源       | `POST /api/auth/login` 返回 `access_token` + `role`，`stores/auth.ts` 持久化 `role`             |

## 6. 关键交互流程

### 6.1 未读徽标链路

1. 后端聚合未读（`GET /api/unread/summary`：`total_unread` + `items`）。
2. `AppLayout` 侧栏「未读文献」概览显示总数，工作台导航项显示红色未读角标；`DashboardView` 概览卡同步显示"未读"指标。
3. 登录返回时携带未读摘要；阅读文献（`POST /api/papers/{id}/read` / 批量 `/api/papers/batch-read`）后调 `auth.refreshUnread()`，角标与文案即时刷新。

### 6.2 新增文献弹窗（New Literature Modal）

1. 工作台点击某方向卡片 → 以 `subscription.id` 打开弹窗（`GET /api/subscriptions/{id}/papers`）。
2. 弹窗内文献按"未读在前"排序（`is_read` 升序，同组内保持相关度序），未读项有红色圆点/浅色底标记。
3. 支持单篇「标记已读」、「全部标记已读」、「关闭」；关闭方式：右上角 X / 底部按钮 / 键盘 `Escape`；打开时锁定 `document.body` 滚动，关闭时恢复。

### 6.3 多步 Agent 问答（QaView）

1. 用户输入或点击预设问题 → 提交 `POST /api/qa/ask`（携带 `mode`：phrase / paragraph / strategy 与 `rewrite` 查询改写开关）。
2. 步骤条由后端 `/steps` 接口驱动，节点为：**查询改写 → 规划调度 → 拆解问题 → 检索文献库 → 检索网络 → 引用历史 → 复审校验 → 汇总答案**；逐步态 `todo → active（转圈）→ done（勾选）`；迭代模式（deep 档位）步骤条右上角展示迭代轮次徽章如「第 2/3 轮」，当前轮次实时更新。
3. 完成后渲染要点答案列表与引用来源卡片（可外链打开）；「多视角综述」结果见 §6.3 第 7~8 条（可编辑大纲）。
4. 思考过程面板：结果区下方默认收起折叠面板，实时追加每一轮的工具调用记录（工具名/入参/返回摘要）与复审日志（Reviewer 质检结果：通过/不通过 + 缺陷清单 + 改进建议），交互支持展开收起；最终结果区域展示迭代次数标签（如"迭代 3 轮"）与复审质检通过标签。
5. 降级回退 v3 固定流水线时，思考过程面板提示文字为【当前使用旧编排流水线，无主 Agent 思考记录】。
6. 组件卸载时统一清理定时器/轮询（`onUnmounted` cleanup）。
7. 综述结果以**大纲编辑器**（`components/OutlineEditor.vue`）呈现：顶部「编辑 / 预览」双态切换；编辑态支持章节增删、层级切换（depth 1~3）、上/下移、标题与正文编辑、为章节挂/摘引用（引用来源为综述 `citations`）；预览态按层级缩进渲染，章节序号按出现顺序自动重算。
8. 点击「导出 Word」→ `POST /api/qa/review/export` 提交当前编辑后的大纲，服务端返回 `.docx` 二进制流，前端以 blob 触发下载（文件名取自 `Content-Disposition`）；**编辑仅前端本地态，刷新即失效、不落库**。

### 6.4 运行跟进（进度反馈）

`DashboardView`「运行跟进」按钮 → 逐方向下发 `POST /api/follow-up/run?subscription_id={id}` 收集 task_id → 轮询 `GET /api/follow-up/tasks/{taskId}` 直至全部进入终态（`success / partial_failed / failed`，404 = 尚未被 worker 领取视为进行中）→ 停止轮询并汇总"成功 / 部分失败 / 失败"提示 → 刷新未读与方向数据。

### 6.5 方向启停 / 编辑 / 删除

- **启停**：列表行启停开关或 Play/Pause 图标，调用启用/停用接口（`Subscription.active`）并即时刷新。
- **编辑**：点击编辑 → 表单以 `initial=当前订阅` 打开并回填全部字段（含 `pub_window` 时间窗口，按逗号拆分回填为多选）。
- **时间范围**：表单内**复选框组**提供三档（1年内 / 1–3年 / 3年以上，新建默认只勾"1年内"），可自由组合、至少勾一项（前端与后端都校验）；表单内部用 `string[]`，保存时 `join(',')` 提交（字段 `pub_window`），多档取并集。
- **删除**：直接删除（当前无二次确认弹窗）。

## 9. 按钮样式规范：米黄胶囊按钮

### 9.1 视觉规范说明

本按钮定位为全局 **主操作 / CTA 按钮**，采用"胶囊 + 扫过覆盖层"特效：

| 属性       | 规范值                               | 说明                     |
| -------- | --------------------------------- | ---------------------- |
| 形状       | 胶囊形（pill）                         | 圆角 `500px`，超椭圆胶囊       |
| 字号 / 字重  | `17px` / `bold`                   | 粗体，主操作突出               |
| 背景色      | `#F0E6C8`（米黄）                     | 原稿为 `#66ff66` 绿色，已改为米黄 |
| 默认文字色    | `#3E3120`（深棕）                     | 与米黄底对比，柔和复古感           |
| 滑过动画     | `::before` 覆盖层 `skew(30deg)` 斜切滑入 | 深棕/黑覆盖层扫过按钮            |
| hover 文字 | 变为米黄 `#F0E6C8`                    | 与覆盖层形成颜色反转效果           |
| 过渡曲线     | `cubic-bezier(0.19, 1, 0.22, 1)`  | 缓入缓出的扫过节奏              |

### 9.2 适配 Vue 的写法

> 本规范为 **Vue SFC** 写法（`<template>` + `<style scoped>`）。CSS 可放入 `src/styles/main.css`（全局）或组件 `<style scoped>`，组件模板使用 `class` 绑定即可，Vue 天然支持伪类与 `:hover`。

**① 完整 CSS（放入 `styles/main.css` 或组件 scoped）**

```css
/* 米黄胶囊按钮 */
.capsule-btn {
  position: relative;
  display: inline-block;
  overflow: hidden;
  padding: 13px 40px;
  border: none;
  border-radius: 500px;          /* 胶囊圆角 */
  background-color: #F0E6C8;     /* 米黄底（原 #66ff66 绿色 → 已改） */
  color: #3E3120;                /* 深棕，默认文字色 */
  font-family: inherit;
  font-size: 17px;               /* 粗体 17px */
  font-weight: 700;
  line-height: 1.2;
  cursor: pointer;
  transition: color 0.4s ease;
}

/* 滑过覆盖层：深棕/黑，skew(30deg) 斜切滑入 */
.capsule-btn::before {
  content: "";
  position: absolute;
  inset: -2px;
  z-index: 0;
  background: #2B2823;           /* 深棕/黑覆盖层 */
  transform: translateX(-120%) skew(30deg);   /* 30deg 斜切，初始位于左侧外 */
  transition: transform 0.5s cubic-bezier(0.19, 1, 0.22, 1);
}

.capsule-btn:hover::before {
  transform: translateX(0) skew(30deg);       /* hover 时覆盖层整体滑入 */
}

/* 文字层置于覆盖层之上，hover 颜色反转 */
.capsule-btn > span {
  position: relative;
  z-index: 1;
  transition: color 0.35s ease;
}

.capsule-btn:hover > span {
  color: #F0E6C8;                /* 覆盖层上，文字变米黄（反转） */
}

.capsule-btn:disabled {
  opacity: 0.6;
  cursor: not-allowed;
}
```

**② Vue 模板使用示例**

```vue

  <span>运行跟进</span>
</button>

<!-- 其他主操作同理 -->

  <span>新建方向</span>
</button>
```

### 9.3 适用页面建议

胶囊按钮作为**主操作（CTA）**使用，建议覆盖以下高频入口，形成一致的品牌化视觉：

| 页面 / 视图                       | 对应按钮       | 建议                         |
| ----------------------------- | ---------- | -------------------------- |
| 工作台（`DashboardView`）          | 「运行跟进」     | 本按钮的核心主操作，优先应用             |

## 10. 复选框样式规范：cl-checkbox

### 10.1 视觉 / 交互规范说明

`cl-checkbox` 为 **Material 风格**复选框，作为全局勾选类控件统一实现：

| 属性            | 规范值                         | 说明                                           |
| ------------- | --------------------------- | -------------------------------------------- |
| 尺寸            | `18px × 18px` 方框            | 圆角 `2px`                                     |
| 未选中态          | 边框 `rgba(0,0,0,0.6)`        | 透明填充                                         |
| 选中态           | 主题色 `#E9DFC3`（暖米黄）填充 + 白色对勾 | 与项目主色一致（原 `#018786` / `#003B2C` 已统一替换为暖米黄）   |
| Ripple 水波纹    | `active` 时 40px 圆形缩放消失      | 从中心扩散后淡出                                     |
| hover / focus | 半透明暗色涟漪                     | `rgba(0,0,0,0.1)` 圆形，键盘 `focus-visible` 同样可见 |
| disabled      | 整体灰化                        | 边框变浅 `rgba(0,0,0,0.26)`，禁用交互                 |
| indeterminate | 支持半选态                       | 主题色填充 + 白色横杠（用于"全选"部分选中）                     |

### 10.2 适配 Vue 的写法

> 本规范为 **Vue SFC** 写法。CSS 可放入 `styles/main.css` 或组件 `<style scoped>`，模板使用 `v-model`（或 `:checked` + `@change`）与 `el.indeterminate` 受控半选态。

**① 完整 CSS（放入 `styles/main.css`）**

```css
/* Material 风格复选框 */
.cl-checkbox {
  position: relative;
  display: inline-flex;
  width: 18px;
  height: 18px;
  vertical-align: middle;
  cursor: pointer;
}

/* 隐藏原生样式：input 作为 18×18 方框本体 */
.cl-checkbox input {
  appearance: none;
  -webkit-appearance: none;
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  margin: 0;
  cursor: pointer;
  outline: none;
  border: 2px solid rgba(0, 0, 0, 0.6);   /* 未选中边框 */
  border-radius: 2px;                       /* 圆角 2px */
  background-color: transparent;
  box-sizing: border-box;
  transition: background-color 0.15s ease, border-color 0.15s ease;
}

/* Ripple 涟漪：hover/focus 显示半透明暗色圆，active 时放大扩为 40px 圆形并淡出 */
.cl-checkbox input::before {
  content: "";
  position: absolute;
  top: 50%;
  left: 50%;
  width: 40px;
  height: 40px;
  border-radius: 50%;
  background: rgba(0, 0, 0, 0.1);           /* 半透明暗色涟漪 */
  transform: translate(-50%, -50%) scale(0);
  opacity: 0;
  transition: transform 0.3s ease, opacity 0.3s ease;
  pointer-events: none;
}

.cl-checkbox input:hover::before,
.cl-checkbox input:focus-visible::before {
  transform: translate(-50%, -50%) scale(1);
  opacity: 0.8;
}

.cl-checkbox input:active::before {
  /* 按压时：40px 圆形缩放扩散并淡出（水波纹消失） */
  transform: translate(-50%, -50%) scale(1.4);
  opacity: 0;
  transition: transform 0.5s ease-out, opacity 0.5s ease-out;
}

/* 选中态：主色填充 + 白色对勾 */
.cl-checkbox input:checked {
  background-color: #E9DFC3;
  border-color: #E9DFC3;
}

.cl-checkbox input:checked::after {
  content: "";
  position: absolute;
  top: 50%;
  left: 50%;
  width: 4px;
  height: 9px;
  border: solid #fff;                        /* 白色对勾 */
  border-width: 0 2px 2px 0;
  transform: translate(-50%, -65%) rotate(45deg);
}

/* 半选态（indeterminate）：主色填充 + 白色横杠 */
.cl-checkbox input:indeterminate {
  background-color: #E9DFC3;
  border-color: #E9DFC3;
}

.cl-checkbox input:indeterminate::after {
  content: "";
  position: absolute;
  top: 50%;
  left: 50%;
  width: 8px;
  height: 2px;
  background: #fff;
  transform: translate(-50%, -50%);
}

/* 禁用态：灰化 */
.cl-checkbox:has(input:disabled) {
  opacity: 0.6;
  cursor: not-allowed;
}

.cl-checkbox input:disabled {
  cursor: not-allowed;
  border-color: rgba(0, 0, 0, 0.26);
}

.cl-checkbox input:disabled:checked,
.cl-checkbox input:disabled:indeterminate {
  background-color: rgba(0, 0, 0, 0.26);
  border-color: rgba(0, 0, 0, 0.26);
}
```

**② Vue 模板使用示例**

```vue
<!-- 单选（v-model） -->
<label class="cl-checkbox">
  <input type="checkbox" v-model="checked" />
</label>

<!-- 半选态（批量全选部分选中）：通过 ref.el 设置 indeterminate -->
<script setup lang="ts">
import { ref } from 'vue'
const allRef = ref<HTMLInputElement>(null)
// 在 watch 中依据"部分选中"设置 allRef.value.indeterminate
</script>
<template>
  <label class="cl-checkbox">
    <input type="checkbox" :ref="allRef" :checked="allChecked" @change="onToggleAll" />
  </label>
</template>

<!-- 禁用 -->
<label class="cl-checkbox">
  <input type="checkbox" checked disabled />
</label>
```

### 10.3 适用页面建议

`cl-checkbox` 适配所有"勾选/启用/多选/筛选"场景，建议以下位置应用：

| 页面 / 视图                       | 场景                          | 建议                                                |
| ----------------------------- | --------------------------- | ------------------------------------------------- |
| 研究方向（订阅）管理（`SubscriptionsView`） | 列表行"启停"、行前"批量选择"、表头"全选"     | 用 checkbox 承载批量选择；全选行的"部分选中"用 indeterminate 半选态   |
| 研究方向（订阅）表单                   | 「采集来源」多选                    | 由当前 chip 多选改为 cl-checkbox 列表，更贴近标准表单语义            |
| 设置页（`SettingsView`）             | 「通知方式」开关、`全局采集来源` 多选        | 邮件/浏览器推送可继续用 Toggle，也可统一为 cl-checkbox；全局来源改为复选框多选 |
| 文献问答（`QaView`）                 | 「查询改写」开关                    | 可统一使用 cl-checkbox（当前为原生 checkbox + accent 色）         |
| 跟进日志（`LogsView`）                | 筛选：按状态 / 来源勾选过滤              | 顶部筛选区使用 cl-checkbox 组，支持多选过滤                      |

> 提示：`Toggle`（现有开关）与 `cl-checkbox` 表达语义略有差异——**开关**用于即时启停，**复选框**用于批量选择/多选/筛选；同一页面建议二选一保持一致，避免混用造成理解成本。
