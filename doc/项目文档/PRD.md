## 2. 产品背景与目标

### 2.1 背景

大学生（本科生 / 研究生）在毕业设计、课程论文、学科竞赛、考研保研等科研学习场景中跟踪最新文献（arXiv 预印本、Semantic Scholar 等），通常依赖手动检索与订阅邮件，存在三大痛点：

1. **高频噪音**：每日新增文献量大，难以从噪音中定位与自身研究方向真正相关的内容；
2. **信息滞后**：人工周期性检索存在空窗，错过最新论文；
3. **阅读负担**：大量全文/摘要需要通读，缺乏聚合、提炼与多视角理解手段。

### 2.2 产品目标

构建一个"定义方向 → 自动跟进 → 主动提示 → 辅助问答与综述"的文献持续跟踪闭环：

- **自动化跟进**：系统周期性自动抓取各研究方向的最新学术文献，增量入库、智能去重；
- **主动提示**：通过前端"未读徽标 + 点击弹窗"主动通知用户新增论文，无需用户主动刷新；
- **智能辅助**：对已入库文献提供多智能体协作式问答与多视角综述，降低阅读理解负担；
- **离线友好**：系统不要求 7×24 常驻在线，支持错过窗口合并补跑。

## 3. 目标用户与场景

本产品面向**大学生（本科生 / 研究生）**，覆盖从课程学习到毕业设计的完整科研学习链路：

| 用户             | 典型场景                    | 核心诉求                 |
| -------------- | ----------------------- | -------------------- |
| 本科生（毕业设计/课程论文） | 毕业论文开题与文献调研、课程论文/文献综述写作 | 快速检索并跟踪相关方向、少漏检、能问答  |
| 本科生（学科竞赛）      | 竞赛选题查新与方案前沿追踪           | 了解领域最新进展、避免重复选题、素材佐证 |
| 研究生            | 研究生课题持续跟进、综述写作          | 周期性跟进、趋势判断、多视角综述     |
| 考研 / 保研学生      | 目标方向与导师研究动态调研           | 梳理方向脉络、跟进目标课题组成果     |

### 典型用户故事

- 作为一名做毕业设计的本科生，我定义一个研究方向"检索增强生成"，系统每天自动跟进最新论文，我登录即可看到未读徽标，点击弹窗浏览新增文献，无需自己反复刷 arXiv，开题报告的参考文献部分因此轻松不少。
- 作为一名准备学科竞赛的本科生，我借助系统对参赛方案进行查新，持续追踪同方向的最新进展，避免重复选题，并随时把这些文献作为方案论证的依据。
- 作为一名研究生，我希望系统以简报形式汇总上个窗口内的新增，并标明去重与筛选结果，减少我为课题综述手动整理的成本。
- 作为一名考研 / 保研学生，我通过系统调研心仪方向与导师团队的研究动态，快速形成脉络清晰的认知。
- 作为大学生用户，我想就对库内文献提问，系统用多智能体协作方式给出带引用来源的回答与多视角综述，帮助我理解文献、写出综述。

## 4. 产品定位与价值

| 维度   | 说明                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------- |
| 定位   | 面向大学生（本科生 / 研究生）的"文献持续跟踪 + 智能问答/综述"助手，服务毕业设计、课程论文、学科竞赛、考研保研等科研学习场景，区别于一次性检索工具（如普通搜索引擎）与通用文献管理库（如 Zotero） |

| 差异化  | 增量游标 + 去重（唯一索引硬去重 + 标题归一化 / FULLTEXT 近似）+ 多 agent 协作（检索路由 / 多视角综述）三者结合                                   |

## 5. 功能需求

> 以下按模块描述功能需求与验收要点。涉及前端视图时与《前端设计文档v2.md》5 大视图对应：工作台 / 研究方向管理 / 文献问答 / 跟进日志 / 设置。

| F-SUB-02 | 编辑研究方向  | 修改名称/关键词/来源/阈值/时间范围；字段校验（如名称非空、至少一个关键词），保存后影响后续跟进                                                                          | P0  |
| F-SUB-03 | 启停订阅    | 启用/停用某方向：停用后不再纳入周期跟进                                                                                                       | P0  |
| F-SUB-04 | 删除/批量删除 | 删除单条或批量删除方向；删除为该数据源全部条目删除                                                                                                  | P1  |
| F-SUB-05 | 来源多选    | 来源候选以固定候选池多选，可组合订阅。候选池含**可用源**（arXiv、Semantic Scholar、万方 Wanfang 等）与**受限/待接入候选**（Google Scholar），各源状态与接入说明见《详细设计文档.md》§3.7 | P1  |
| F-SUB-06 | 阈值配置    | 相关度阈值以滑杆配置，低于阈值的新增论文不入库                                                                                                    | P1  |
| F-SUB-07 | 试跑预览    | 新建/编辑时可对样例请求做本地"试跑预览"，展示若干候选结果但不实际改动                                                                                       | P2  |
| F-SUB-08 | 时间范围设置  | 新建/编辑方向时可多选文献发表时间范围，候选三档：**1年内 / 1–3年 / 3年以上**（默认仅"1年内"，至少选一档）；多档取**并集**，如同时选"1年内"与"3年以上"表示跳过 1–3 年。用于限制跟进抓取/过滤时按发表时间（`published_at`）收录文献的时间跨度，详见《详细设计文档.md》§2.2/§4.4   | P1  |

| F-QA-11 | 主Agent智能调度  | 主Agent自主拆解用户问题为子任务，动态匹配问题复杂度（quick/normal/deep），自主调用检索工具与分析Agent完成多步协作                                                 | P1  |

### 5.8 权限与角色（RBAC，对应管理端视图）

> 系统引入**基于角色的访问控制（RBAC）**：仅两种角色——`user`（普通用户）与 `admin`（管理员）。普通用户可访问现有全部功能模块（§5.1~§5.7）；管理员权限独立于普通用户，本期仅开放「用户管理」「模型配置」两个管理端模块，**后续将陆续扩展更多管理功能，设计预留扩展位**。

**角色与权限矩阵**

| 角色              | 可访问范围                                         |
| --------------- | --------------------------------------------- |
| `user`（普通用户，默认） | 全部现有模块：方向订阅管理、文献跟进、未读提示与弹窗、文献问答、多视角综述、跟进日志、设置 |
| `admin`（管理员）    | 仅管理端：用户管理、模型配置（后续扩展预留）                        |

**管理端功能点**

| 编号        | 需求        | 说明                                                | 优先级 |
| --------- | --------- | ------------------------------------------------- | --- |
| F-RBAC-01 | 角色字段      | `users.role` 区分普通用户/管理员，默认 `user`                 | P1  |
| F-RBAC-02 | 登录携带角色    | 登录 Bearer token 中携带 `role`，前端据此做菜单显隐与路由守卫         | P1  |
| F-RBAC-03 | 后端管理接口鉴权  | `/api/admin/**` 系列接口增加 admin 角色校验，非 admin 返回 403  | P1  |
| F-RBAC-04 | 用户管理（管理端） | 用户列表、启用/停用状态、角色调整（user⇄admin）；仅管理员可访问             | P1  |
| F-RBAC-05 | 模型配置（管理端） | 管理端维护全局模型参数与模型选择（与《AI方案文档.md》模型选型/动态路由联动）；仅管理员可访问 | P2  |
| F-RBAC-06 | 前端路由守卫    | 管理员仅见「用户管理」「模型配置」两管理入口；普通用户不可见管理入口                | P1  |
| F-RBAC-07 | 管理员初始化    | 首次部署时初始化管理员账号，方案见《详细设计文档.md》§3.8                  | P1  |

### 5.9 管理员端 · 模型管理（F-MODEL，管理员专属）

> 归属：`admin` 管理端模块（见 §5.8），接口走 `/api/admin/**` + `require_role("admin")` 拦截，普通用户不可见不可访问。功能目标：把 AI 环节使用的模型从"代码内硬编码"变为"管理端可维护的模型池 + 按 agent 绑定"，实现**添加模型、停用模型、为 agent 设置模型**三项闭环（与《AI方案文档.md》§1.1 模型分层/动态路由、§2 多 agent 联动）。

| 编号         | 需求           | 说明                                                                                                                                                                       | 优先级 |
| ---------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --- |
| F-MODEL-01 | 添加模型         | 管理员新增模型配置，建议字段：模型显示名、模型标识 `model_id`、所属供应商/平台、`base_url`、`api_key`（**仅服务端存储**，禁止下发前端/返回给客户端）、能力标签（`chat` / `embedding` / `vision`，可多选）、是否默认；编号唯一性（同供应商下 `model_id` 唯一）校验 | P1  |
| F-MODEL-02 | 停用模型         | 模型 `status` 启用/停用切换（管理端列表开关 + `PATCH` 接口）；停用后**不可再被选用**（新绑定/新建方向的下拉不出现该模型），**不影响已在进行中的任务**（进行中会话继续使用已加载实例）                                                               | P1  |

## 7. 非功能需求

### 7.1 性能

| 项    | 要求                                                         |
| ---- | ---------------------------------------------------------- |
| 前端首屏 | 首屏可交互时间目标 ≤ 2s（本地部署，静态资源可预测）                               |
| 接口响应 | 读接口（订阅列表/未读/日志）P95 ≤ 500ms；问答为异步多步，不适用同步指标，按"步骤可见、可感知推进"设计 |
| 跟进吞吐 | 单次跟进单方向在分钟级完成（取决于来源网络延时与文献量），失败可重试                         |
| 数据库  | MySQL 连接池复用 + FULLTEXT/普通索引；单方向检索 P95 ≤ 300ms              |

### 7.2 可用性 —— 非在线容错（核心）

系统**不假设 7×24 常驻在线**，通过以下机制保证"错过窗口不丢"。详细机制见《总体设计文档.md》§8 与《详细设计文档.md》§4.5：

1. **游标增量**：`last_run_at` 游标记录上次跟进位置，恢复后只拉增量；
2. **调度 coalesce 合并**：错过多个调度窗口时，迟到启动合并为一个跟进任务处理，不重复不遗漏；
3. **登录惰性触发**：用户登录成功即"下发跟进单"（重活异步执行），前端轮询/WebSocket 刷新结果；
4. **迟到合并简报**：合并补跑完成后生成一份合并简报，未读徽标一次性反映。

### 7.3 合规

- 数据源合规：遵守 arXiv / Semantic Scholar 等数据源 API 使用条款与限速要求，实现**限速与退避**（指数退避），请求失败自动退让；
- RAG/向量检索阶段暂缓：当前库内检索采用 MySQL 全文检索 + 元数据过滤；若后续引入 RAG，需保证 embedding 选型定死、向量可比（详见《AI方案文档.md》）；
- 网络检索需标识来源、保留引用链接。

### 7.4 可观测性

- 每次跟进写入 `task_logs`，含起始/结束时间、方向、来源、拉取/新增/去重计数、耗时、状态；
- worker 任务队列具备任务级日志（task id 贯穿），支持失败定位；
- 前端日志视图 + 后端日志文件/控制台双重可见。

### 7.5 安全

- 用户鉴权：登录接口返回会话凭据，前端存储并携带；敏感配置（API Key、数据库口令）仅存于服务端环境变量，禁止下发前端；
- 角色鉴权：Bearer token 携带角色；`/api/admin/**` 管理接口由后端按 admin 角色拦截（非 admin 返回 403）；前端路由守卫 + 菜单按角色显隐；
- 数据隔离：多用户场景按用户维度隔离订阅与文献读权限（本期可单人部署起步，设计预留 user_id 维度）；
- 备份：`mysqldump` 定期备份 MySQL 8（含库内全文数据），提供恢复指引；
- Prompt 注入防护：外部拉取的文献文本不做指令执行，仅作为数据输入（详见《AI方案文档.md》§7）。
