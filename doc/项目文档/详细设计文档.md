## 2. 数据库表结构设计

> **表结构权威**：以 `app/models.py`（SQLAlchemy 2.0 ORM 模型）为**唯一权威**，由 `Base.metadata.create_all()` 负责建表；原 `app/schema.sql` 已删除。下文各表为按该权威文档化的等价视图。
>
> **数据访问**：**SQLAlchemy 2.0 ORM + PyMySQL 驱动**（会话/事务模型见《数据库ORM迁移设计.md》§6）；仅 `papers` 的 FULLTEXT `MATCH ... AGAINST` 检索保留原生 SQL（经 `engine.exec_driver_sql`，见设计 §6.4 豁免）。
>
> 存储：MySQL 8（InnoDB, utf8mb4）。所有表启用 `id` 主键；时间字段统一 `DATETIME`；文本默认 utf8mb4（支撑中文全文检索）。

### 2.1 `users`——用户表

| 字段 | 类型 | 约束/索引 | 说明 |
|---|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | PK | 用户主键 |
| `username` | VARCHAR(64) | UNIQUE NOT NULL | 登录名 |
| `password_hash` | TEXT | NOT NULL | 口令哈希（服务端只存哈希） |
| `role` | ENUM('user','admin') | NOT NULL DEFAULT 'user'; INDEX | 角色：`user`=普通用户（默认，可用全部现有模块）、`admin`=管理员（仅管理端模块，后续扩展预留） |
| `status` | ENUM('active','disabled') | NOT NULL DEFAULT 'active' | 账号状态：启用 / 停用（停用禁止登录，可在「用户管理」调整） |
| `created_at` | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `last_login_at` | DATETIME | — | 最近登录时间（用于惰性触发判断） |

### 2.2 `subscriptions`——研究方向订阅表

| 字段 | 类型 | 约束/索引 | 说明 |
|---|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | PK | 订阅主键 |
| `user_id` | FK → users.id | NOT NULL; INDEX | 所属用户 |
| `name` | VARCHAR(128) | NOT NULL | 方向名称 |
| `keywords` | JSON | NOT NULL DEFAULT ('[]') | 关键词集合 |
| `sources` | JSON | NOT NULL DEFAULT ('[]') | 来源集合候选值 |
| `threshold` | DOUBLE | NOT NULL DEFAULT 0.5 | 相关度阈值 |
| `pub_window` | VARCHAR(32) | NOT NULL DEFAULT '1Y' | **文献发表时间窗口（可多选）**：逗号分隔存多个值，如 `1Y,3Y+`；1Y=近1年内、1_3Y=1–3年内、3Y+=3年以上，多个窗口取**并集**（跟进时按 `published_at` 叠加过滤，见 §4.4 层1；抓取侧截断见 §4.2） |
| `active` | BOOLEAN / TINYINT(1) | NOT NULL DEFAULT 1 | 是否启用（停用不纳入调度） |
| `last_run_at` | DATETIME | — | 上次跟进游标（增量依据） |
| `created_at` / `updated_at` | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 时间戳（updated_at 由应用更新） |

### 2.3 `papers`——文献主表

| 字段 | 类型 | 约束/索引 | 说明 |
|---|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | PK | 文献主键 |
| `external_id` | VARCHAR(255) | **UNIQUE NOT NULL** | 数据源唯一标识 / DOI（硬去重依据） |
| `source` | VARCHAR(32) | NOT NULL; INDEX | 来源（arxiv / semanticScholar 等） |
| `title` | TEXT | NOT NULL; **FULLTEXT** | 题名（参与全文检索） |
| `authors` | JSON | DEFAULT ('[]') | 作者集合 |
| `abstract` | TEXT | DEFAULT ''; **FULLTEXT** | 摘要（参与全文检索） |
| `journal` | TEXT | DEFAULT '' | 期刊/出处 |
| `published_at` | DATE | INDEX | 发表时间 |
| `url` | TEXT | — | 原文链接 |
| `raw_meta` | JSON | — | 数据源码元数据（供溯源/排查） |
| `created_at` | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 入库时间 |

索引/约束：
- `(source, external_id)` 唯一约束（双保险硬去重；DOI 命中亦视为重复）；
- `title`/`abstract` 建 FULLTEXT 全文索引（ngram parser 支持中文）：`CREATE FULLTEXT INDEX idx_papers_fulltext ON papers(title, abstract) WITH PARSER ngram`；
- `published_at` 普通索引（按时间筛选/排序）。

### 2.4 `subscription_papers`——方向-文献关联表（含未读）

| 字段 | 类型 | 约束/索引 | 说明 |
|---|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | PK | 主键 |
| `subscription_id` | FK → subscriptions.id | NOT NULL; INDEX | 关联订阅 |
| `paper_id` | FK → papers.id | NOT NULL; INDEX | 关联文献 |
| `score` | DOUBLE | — | 三层打分后的相关度得分 |
| `is_read` | BOOLEAN / TINYINT(1) | NOT NULL DEFAULT 0; INDEX | **未读标记**（驱动徽标） |
| `read_at` | DATETIME | — | 已读时间 |
| `created_at` | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 入库时间 |

约束：
- `UNIQUE(subscription_id, paper_id)`：同方向不重复关联同一文献（配合标题归一化 / FULLTEXT 去重后最终写入）；
- `is_read + subscription_id` 组合索引支撑未读统计查询。

### 2.5 `task_logs`——跟进/任务日志表

| 字段 | 类型 | 约束/索引 | 说明 |
|---|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | PK | 日志主键 |
| `task_id` | VARCHAR(64) | INDEX | 任务/跟进单唯一标识（贯穿 worker 日志） |
| `kind` | VARCHAR(32) | INDEX | 类型：schedule / login_trigger / manual / question |
| `subscription_id` | FK → subscriptions.id | NULLABLE | 关联方向（全局任务可空） |
| `direction_name` | VARCHAR(128) | — | 方向名快照（避免索引外键读） |
| `source` | VARCHAR(32) | — | 数据源 |
| `pulled` / `added` / `deduped` | INTEGER | NOT NULL DEFAULT 0 | 拉取 / 新增 / 去重计数 |
| `duration` | INTEGER | — | 耗时（ms） |
| `status` | VARCHAR(16) | INDEX | success / partial_failed / running / failed |
| `detail` | JSON | — | 扩展详情（错误、筛选记录等） |
| `started_at` / `finished_at` | DATETIME | — | 起止时间 |

### 2.6 建表清单（汇总）

| 表 | 用途 | 关键索引/约束 |
|---|---|---|
| `users` | 用户 | username UNIQUE |
| `subscriptions` | 订阅 | user_id INDEX |
| `papers` | 文献主表 | external_id UNIQUE；(title,abstract) FULLTEXT（ngram）；published_at INDEX |
| `subscription_papers` | 关联 + 未读 + 得分 | (subscription_id,paper_id) UNIQUE；(is_read, subscription_id) INDEX |
| `task_logs` | 可观测 | task_id / status INDEX |
| `models` | 模型池（管理员维护） | UNIQUE(vendor, model_id)；status / capability INDEX |
| `agent_model` | agent ↔ 模型绑定（管理员维护） | agent_key UNIQUE，FK → models.id |
| `settings` | 用户设置（调度频率 / 通知 / 来源池） | user_id UNIQUE，FK → users.id |

**模型 ↔ 表对照（8 模型 / 8 表，权威定义见 `app/models.py`）**

| 模型类（ORM） | 表名 | 说明 |
|---|---|---|
| `User` | `users` | 用户 |
| `Subscription` | `subscriptions` | 研究方向订阅 |
| `Paper` | `papers` | 文献主表 |
| `SubscriptionPaper` | `subscription_papers` | 方向-文献关联（含未读 / 得分） |
| `TaskLog` | `task_logs` | 跟进 / 任务日志 |
| `LlmModel` | `models` | 模型池 |
| `AgentModel` | `agent_model` | agent ↔ 模型绑定 |
| `Setting` | `settings` | 用户设置 |

> **本地静态元数据映射表（不入库，代码级注入）**：期刊等级 / CCF 分级 / 中科院分区 / arXiv 分类等以本地静态文件（如 JSON）随代码维护，**不入库、零 LLM**。展示/重排前按 `ISSN → 期刊名` 多级回退匹配注入（详见 §4.6「展示前元数据增强」），避免每次跟进重复查询外部服务。

### 2.7 模型管理相关表（管理员，RBAC）

> 归属 `admin` 管理端，仅管理员可读写；接口见 §3.8。设计目标：把 AI 环节所用模型从"代码硬编码"改为"模型池 + agent 绑定"的可配置形态（对应 PRD §5.9 F-MODEL-01~05）。

**`models`（模型池）**

| 字段 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | PK |
| `name` | VARCHAR(64) | NOT NULL；模型显示名 |
| `model_id` | VARCHAR(128) | NOT NULL；模型标识（如 `deepseek-chat`），同供应商下唯一；UNIQUE(vendor, model_id) |
| `vendor` | VARCHAR(64) | NOT NULL；供应商/平台（deepseek / openai / ollama / 本地 qwen 等） |
| `base_url` | VARCHAR(512) | 可空；接入地址，空 = 官方默认 |
| `api_key_enc` | VARCHAR(512) | 可空；`api_key` 仅服务端存储（加密列或环境变量引用占位），**所有接口不回传明文** |
| `capabilities` | JSON | 能力标签：`["chat"]` / `["embedding"]` / `["vision"]` / `["function_call"]` 可组合，用作绑定/选用校验（`function_call` 为 Planner / Reviewer 绑定的必需能力，见 §3.8） |
| `is_default` | TINYINT(1) | NOT NULL DEFAULT 0；是否默认（每类用途同一时刻唯一默认，写入时由应用层保证） |
| `status` | ENUM('active','disabled') | NOT NULL DEFAULT 'active'；`disabled` 后不可再被选用、不影响进行中任务 |
| `extra` | JSON | 参数：温度 / max_tokens / 超时 / 并发上限等 |
| `created_at` / `updated_at` | DATETIME | 记录时间 |

**`agent_model`（agent ↔ 模型绑定）**

| 字段 | 类型 | 约束 / 说明 |
|---|---|---|
| `agent_key` | VARCHAR(32) | PK；agent 标识（`main` / `planner` / `reviewer` / `qa_router` / `retriever` / `summarizer` / `analyst-method` / `analyst-critic` / `analyst-compare` 等，映射见《AI方案文档.md》§2.1） |
| `model_id` | BIGINT | FK → `models.id`，NOT NULL；该 agent 实际调用的模型 |
| `updated_by` | BIGINT | FK → `users.id`，本次绑定的管理员（audit） |
| `updated_at` | DATETIME | 绑定/切换时间 |

> **停用语义**：`models.status='disabled'` 的模型不进入任何"可选下拉"（F-MODEL-03 的 agent 绑定、F-MODEL-01 之后的选用均只列出启用模型）；已在进行中的任务/会话继续使用已加载实例，**不受停用影响**（F-MODEL-02）。**默认兜底**：某用途若绑定了被停用的模型，`LlmProvider` 按"同用途 `is_default=1` 且 `status='active'`"回退，链路不中断（F-MODEL-05，对齐《AI方案文档.md》§6）。

## 3. API / 接口设计

> 统一 JSON；鉴权头 `Authorization: Bearer <token>`（登录返回）；错误统一 `{code, message, detail?}`；分页参数 `page/limit`。

### 3.1 认证

| 方法与路径 | 说明 | 关键行为 |
|---|---|---|
| `POST /api/auth/login` | 登录 | ①校验凭据（含账号 `status='active'`，停用拒绝登录）；②**下发跟进单**（写队列）；③**不阻塞**返回已入库总览（未读数、方向列表、日志摘要）与 **Bearer token（携带 `role`，如 `{access_token, token_type, role, ...}`）**；④登记 `last_login_at` |
| `POST /api/auth/logout` | 登出 | 失效会话 |

### 3.2 订阅管理

| 方法与路径 | 说明 |
|---|---|
| `GET /api/subscriptions` | 列表（含每方向未读数由 `GET /api/unread/summary` 提供或内联） |
| `POST /api/subscriptions` | 新建（名称/关键词/来源/阈值校验） |
| `PUT /api/subscriptions/{id}` | 编辑（不可改 id；可改字段校验） |
| `PATCH /api/subscriptions/{id}/active` | 启停 |
| `DELETE /api/subscriptions/{id}` | 删除单个（级联删除关联及其阅读状态） |
| `POST /api/subscriptions/batch-delete` | 批量删除（id 数组） |

### 3.3 未读

| 方法与路径 | 说明 |
|---|---|
| `GET /api/unread/summary` | 总未读 + 各方向未读（徽标数据源） |
| `GET /api/unread/{subscriptionId}` | 某方向未读文献列表 |
| `GET /api/subscriptions/{id}/papers` | 某方向全部文献（含已读；工作台方向详情弹窗数据源，未读在前排序） |
| `POST /api/papers/{paperId}/read` | 单篇标记已读 |
| `POST /api/papers/batch-read` | 批量标记已读（{subscriptionId, paperIds[]}） |
| `POST /api/subscriptions/{id}/read-all` | 一键全部已读 |

### 3.4 跟进

| 方法与路径 | 说明 |
|---|---|
| `POST /api/follow-up/run` | 手动触发"运行跟进"：下发跟进单，立即返回 `{task_id, status:'queued'}`（异步） |
| `GET /api/follow-up/tasks/{taskId}` | 查询任务状态/进度（前端轮询依据） |
| `GET /api/logs` | 跟进日志列表（分页 + 状态筛选 `?status=`） |

### 3.5 问答

| 方法与路径 | 说明 |
|---|---|
| `POST /api/qa/ask` | 发起提问：返回会话 id；服务端启动查询改写 + 检索路由（多 agent）。请求体支持 `mode`（`phrase`/`paragraph`/`strategy` 三形态）、`rewrite`（是否走 LLM 查询改写，默认开启；失败回退原始 query，见《AI方案文档.md》§2.5）与 `enable_planner`（默认 true；关闭则强制使用 v3 固定流水线） |
| `GET /api/qa/{sessionId}/steps` | 轮询多步状态（8 节点：查询改写→规划调度→拆解问题→检索文献库→检索网络→引用历史→复审校验→汇总答案，含各步状态；前端步骤条节点详见《前端设计文档v2.md》§6.3）；编排模式下新增字段：`loop_counter` 迭代轮次、`tool_calls` 工具调用记录、`review_notes` 复审意见 |
| `GET /api/qa/{sessionId}/result` | 拉取最终回答（含引用来源）；编排模式下新增字段：`planner_notes` 主 Agent 决策记录、`iteration_count` 迭代次数；综述会话另附 `sections`（分视角小节）与 `outline`（可编辑大纲） |
| `POST /api/qa/review` | 多视角综述（deep 档位）：以 `sections` 分区返回综述结果；`result` 附 `outline`——可编辑大纲（有序数组，节点 `{id, depth, title, content, citations}`；`depth` 为章节层级；`citations` 存引用序号，指向 `citations[]` 下标 +1） |
| `POST /api/qa/review/export` | 综述导出 Word（F-REV-05）：请求体 `{title, outline, citations}`（用户编辑后的大纲）→ 返回 `.docx` 二进制流（`StreamingResponse`，media_type `application/vnd.openxmlformats-officedocument.wordprocessingml.document`，`Content-Disposition` 附文件名）；服务端按 `depth` 生成标题层级、附参考文献列表；**编辑内容不落库** |

### 3.7 数据源接入清单（随真实拉取实测更新）

### 4.2 游标增量抓取

```
function incremental_fetch(sub):
    cursor = sub.last_run_at                     # 游标
    since = cursor ?? sub.created_at             # 首次跟进取创建时间
    for source in sub.sources:
        fetch_since(source, since)               # 来源适配器：分页、限速(退避)、只取增量
    return raw_papers                            # 候选集合
```

要点：`since` 严格采用游标；来源 API 需支持"按时间过滤"或提供 Last-Modified 语义；每次成功完成才推进 `last_run_at`（不成功不推进，保证不丢）。

**时间窗截断**：抓取侧再叠加 `sub.pub_window` 发表时间窗口（字段见 §2.2，可多选）——若选中 `3Y+`（存在无下界区间），直接按游标拉取；否则把 `since` 与所选各窗口下界的**最早者**取更早作为抓取起点，并在入库前按 `published_at` 是否落入所选窗口的**并集**做截断，既减少不必要拉取量，也保证"发表时间范围"设置生效（窗口到 `published_at` 区间的映射见 §4.4 层1）。

### 4.3 去重

```
function dedup(raw_papers):
    kept = []
    for p in raw_papers:
        if hard_dup(p):                          # external_id/DOI 已存在（唯一索引兜底）
            continue
        if title_norm_dup(p):                    # 标题归一化比对（去大小写/空格/标点）
            continue
        if fulltext_approx_dup(p):               # FULLTEXT 近似匹配兜底（低阈值召回疑似重复）
            continue
        kept.append(p)
    return kept
```

- 硬去重：`INSERT ... ON DUPLICATE KEY UPDATE ...` 或 `INSERT IGNORE`（MySQL 唯一索引兜底/索引级保证）；
- 标题归一化去重：标题归一化（去大小写/空格/标点）后比对判重；
- FULLTEXT 近似兜底：对 `title/abstract` 做 FULLTEXT 低阈值近似匹配，命中且相似度达阈值判为疑似重复（阈值详见《AI方案文档.md》）。

### 4.4 筛选（三层打分）

```
function rank_and_filter(papers, sub):
    # 层1 元数据过滤：来源、发表时间窗口、分类/作者/日期/关键词（快，确定性）
    #   发表时间窗口 = sub.pub_window（逗号分隔多选）→ published_at 落入任一窗口即保留：
    #       '1Y'   → published_at >= now - 1年
    #       '1_3Y' → now - 3年 <= published_at < now - 1年
    #       '3Y+'  → published_at < now - 3年（存在无下界区间，抓取侧按游标拉取，见 §4.2）
    #   无 published_at：所选窗口里存在任一非 '3Y+' 项则保留，纯 '3Y+' 才丢弃
    # 层2 关键词/FULLTEXT 命中打分：MATCH(title, abstract) AGAINST('关键词') 得 BM25 风格 base_score
    # 层3 可选 LLM 精筛：对接近阈值的候选用轻量模型判定相关性（成本可控）
    final_score = combine(base_score, rule_factors)
    return [p for p if final_score >= sub.threshold]   # 按 score 排序
```

### 4.5 结果重排（rerank 抽象层）

> 定位：检索层的**分层重排**——MySQL FULLTEXT 负责"检索召回"（类 BM25 命中打分，见 §4.4 层2），rerank 层负责"结果排序"（对已召回结果集做跨源统一重排），二者独立演进。

```python
def rerank(query, ranked_results):
    # 抽象接口 reranker.rerank(query, results) -> sorted
    # 默认实现 BM25Okapi（rank_bm25）：对 title+abstract 拼接文本 BM25 打分
    bm25 = BM25Okapi([tokenize(p.title + ' ' + p.abstract) for p in ranked_results])
    scores = bm25.get_scores(tokenize(query))
    return sorted(zip(ranked_results, scores), key=lambda x: -x[1])

# 未来升级：embedding 重排实现同一 reranker 接口（余弦相似度），
# 仅替换 default_reranker，业务层与前端零改动；API 失败可回退 BM25（本地兜底）
```

- **输入**：查询改写后的结构化检索式（或原始 query）+ 召回结果集（可跨来源，如文献库 + 实时网络）；
- **输出**：统一相关度得分排序后的 top-k 结果；
- **与 FULLTEXT 分层**：FULLTEXT 召回 → rerank 精排 → 元数据增强（§4.6）；
- **兜底**：重排实现异常时降级为原始召回顺序，不阻断主流程（对齐"失败回退"原则）。

worker_loop():

## 8. 错误处理与重试

### 8.1 分层错误处理

| 层 | 处理策略 |
|---|---|
| 前端 | 接口失败统一提示（toast）；`runFollowUp` 进行中防重复点击（`followUpRunning` 锁）；问答步骤失败单独标红可重试 |
| 后端 API | 参数校验 422、鉴权 401、**权限不足 403（非 admin 访问管理接口）**、资源不存在 404、限流 429；统一错误体 |
| worker | RetryableError（来源 429/超时/瞬时）重试退避；FatalError（配置错误/表结构异常）落 failed 不重试 |
| 外部数据源 | 适配层指数退避 + 单个来源失败不影响其他来源（PARTIAL_FAILED） |
| Planner层 | Function-call解析失败、输出非法 → 自动降级v3固定流水线 |
| Reviewer层 | 异常/输出非法 → 跳过质检，直接进入汇总，标注「本次回答未经完整质检，仅供参考」 |
| 子Agent层 | 单个分析师失败 → 对应视角置空，其余视角正常输出 |

### 8.2 重试参数

| 场景 | 策略 |
|---|---|
| 来源 API 限速/失败 | 指数退避 `2^n s + jitter`，上界 60s，单次跟进内最多 3 次 |
| worker 任务失败 | 队列级重试，上限 3 次 |
| FULLTEXT/索引维护失败 | 独立任务重试；持续失败标记该批次，下窗口重来 |
| 登录惰性触发下发失败 | 不阻塞登录（日志告警）；由下一调度窗口兜底补齐 |
